# ✨ Novagram

**Novagram** — кроссплатформенный мессенджер с веб- и Android-клиентом, построенный на React, TypeScript и Supabase.

Проект предоставляет обмен сообщениями в реальном времени, пользовательские профили, медиафайлы, реакции, статусы присутствия и настраиваемое оформление интерфейса. Android-версия собирается с использованием Capacitor и распространяется в виде APK.

## Возможности

* ⚡ **Обмен сообщениями в реальном времени** — доставка сообщений через Supabase Realtime
* 🔐 **Аутентификация** — регистрация и вход через Supabase Auth
* 👤 **Профили пользователей** — имя пользователя, аватар и дополнительная информация
* 🟢 **Статус присутствия** — отображение текущего статуса пользователя
* ✍️ **Индикатор набора текста** — отображение состояния «печатает...»
* 🖼️ **Медиафайлы** — загрузка изображений и файлов через Supabase Storage
* ❤️ **Реакции на сообщения** — эмодзи-реакции с синхронизацией в реальном времени
* 💬 **Управление чатами** — создание, удаление и просмотр диалогов
* 🔔 **Push-уведомления** — доставка уведомлений на Android через Firebase Cloud Messaging
* 🌓 **Светлая и тёмная темы**
* 🎨 **Цветовые палитры** — несколько вариантов оформления интерфейса с отдельными вариантами для светлой и тёмной темы
* 🔄 **Проверка обновлений** — клиент может проверять наличие новой версии через GitHub Releases
* 📱 **Адаптивный интерфейс** — поддержка настольных и мобильных устройств
* 📦 **Android-клиент** — сборка приложения через Capacitor

## Темизация

Novagram поддерживает две базовые темы:

* **Dark**
* **Light**

Дополнительно доступны цветовые палитры:

* **Novagram** — стандартная
* **Ocean** — холодная синяя
* **Forest** — зелёная
* **Lavender** — фиолетовая
* **Amber Dusk** — тёплая бежево-янтарная

Каждая палитра содержит отдельные наборы цветов для светлой и тёмной темы.

Например, **Amber Dusk** может выглядеть как светлое бежево-белое оформление или как тёмное коричнево-серое оформление при переключении темы.

Выбранная тема и палитра сохраняются локально и восстанавливаются при следующем запуске приложения.

## Android

Android-клиент использует Capacitor поверх веб-приложения.

Основной цикл сборки:

```bash
npm install
npm run build
npx cap sync android
npx cap open android
```

После открытия проекта в Android Studio приложение можно собрать в формате APK.

Версия Android-приложения хранится в конфигурации нативного проекта и изменяется при подготовке нового релиза.

## Push-уведомления

Для Android используется Firebase Cloud Messaging.

Клиент:

1. запрашивает разрешение на уведомления;
2. регистрируется в FCM;
3. получает FCM-токен;
4. сохраняет токен пользователя в Supabase.

Отправка уведомлений выполняется через Supabase Edge Function.

Общая схема:

```text
Новое сообщение
       │
       ▼
  Supabase
       │
       ▼
Edge Function
       │
       ▼
 Firebase FCM
       │
       ▼
 Android-клиент
```

## Обновления приложения

Android-клиент поддерживает проверку новой версии через GitHub Releases.

При запуске приложения:

```text
Текущая версия
      │
      ▼
GitHub Releases API
      │
      ▼
Сравнение версий
      │
 ┌────┴────┐
 ▼         ▼
Актуальна  Доступно обновление
              │
              ▼
         Update Modal
```

Это позволяет пользователю узнать о наличии новой версии непосредственно из приложения.

## Локальная разработка

### Требования

* Node.js
* npm
* Android Studio — для Android-сборки
* JDK 21 — для современной конфигурации Android/Gradle
* Supabase project
* Firebase project — для push-уведомлений

### Установка

```bash
npm install
```

### Переменные окружения

Создайте `.env.local` в корне проекта:

```env
VITE_SUPABASE_URL=your_supabase_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

### Запуск dev-сервера

```bash
npm run dev
```

После запуска Vite приложение будет доступно локально.

### Production-сборка

```bash
npm run build
```

Результат сборки помещается в каталог `dist/`.

## Версионирование

Версии приложения выпускаются последовательно:

```text
1.0.1
1.0.2
1.0.3
...
```

Каждый релиз Android сопровождается обновлением версии нативного приложения и публикацией соответствующего APK.

## Структура backend

Supabase используется как основной backend приложения и отвечает за:

* аутентификацию;
* хранение пользователей;
* сообщения и чаты;
* реакции;
* realtime-события;
* хранение файлов;
* регистрацию FCM-токенов;
* серверную логику Edge Functions.

Таким образом, клиентское приложение не содержит собственной серверной инфраструктуры и взаимодействует с backend через Supabase API и Realtime.

## Статус проекта

Novagram находится в активной разработке.

Основная архитектура приложения уже сформирована: реализованы клиентская часть, авторизация, realtime-взаимодействие, работа с файлами, Android-сборка, система тем и палитр, а также инфраструктура push-уведомлений и обновлений.

Некоторые второстепенные функции продолжают дорабатываться.
